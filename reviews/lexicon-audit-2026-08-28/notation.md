# Mathematical notation audit

These are proposed naming decisions, not changes to the articles or implementation. Names below use readable mathematical/Typst spellings. Native literature notation can remain in a local derivation if its mapping to the repository vocabulary is stated. Do not try to give every letter exactly one meaning across unrelated fields: qualify the quantities that cross article boundaries.

The [complete term catalogue](catalogue.md) and [all source locations](evidence.md) cover the associated concepts. `lexical-index.json` also contains every extracted dollar-delimited expression and every mathematical token occurring in multiple files. That mechanical index includes operators, textual subscripts and syntax; it is not a semantic variable parser. Inline Unicode notation and code examples are additionally searched by the term catalogue.

## Conventions already worth preserving

- `N_E` and `N_I` usually work well for population sizes; extend this pattern rather than inventing a new one.
- `C_m`, `g_L`, `E_L`, `V_th`, `V_reset`, `tau_AMPA`, `tau_GABA` and `tau_ref` already form a useful biophysical vocabulary. The missing pieces are consistent population/polarity indices and units.
- Exact API names such as `MeanVoltage`, `SpikeRate`, `ExecutionSpec`, `GraphRuntimeState` and `SpikeBudgetPenalty` should remain exact. A lexicon records their prose names and scope rather than renaming public interfaces casually.
- Units must be part of each shared definition. The legacy biophysical ledger uses ms/mV/nF/μS/nA; graph parameter declarations can use nS; output-LIF voltage can be dimensionless. These are compatible only through explicit mappings, not a blanket “all voltages are mV” rule.
- Keep a short local symbol definition in every standalone article. The shared lexicon should eliminate repeated invention, not make an article unintelligible without another file open.
