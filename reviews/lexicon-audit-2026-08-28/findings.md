# Decisions to make before adopting a lexicon

This is a source audit, not a verdict about what retained runs actually executed. The linked passages are evidence of wording and notation; implementation, run payloads and figures were not re-executed or authenticated. Proposed names are proposals, not established repository policy. All remaining recurring concepts are in the [full catalogue](catalogue.md).

## 3. Source identifiers, helpers and repository vocabulary

- **Percentage formatting has incompatible input contracts.** `pct` accepts already-percent values in [exp076:28](/Users/eoin/pinglab/writings/exp076.typ:28), but multiplies fractions by 100 in [exp080:31](/Users/eoin/pinglab/writings/exp080.typ:31). Use `pct_from_fraction` / `pct_from_percent`, or one helper with an explicit scale. Keep percentage points separate from relative percent changes.
- **Aliases are local, not automatically defects.** `r`, `run`, `cfg`, `c`, `p` and report-number bindings repeat widely. The machine index lists all repeated declarations and inline-code identifiers. Standardize shared schema/API names first; do not require every local report alias to be globally unique.
- **Backend, executor, target, device and provider are separate axes.** Preserve the distinctions in the API articles; “graph” is not automatically a hardware backend. The catalogue separately covers graph, authoring network, compiled bundle, runtime state, training checkpoint and execution request.
- **Experiment, article, condition, run and presentation are different identities.** The catalogue separates them from trained-model bank, output payload, logical asset and snapshot. A read-only presentation `catalogue` binding should not be interpreted as permission for a persistent operational storage catalogue.
- **Legacy field names need explicit maps.** Examples include `theta_u`, `rate_target_hz`, `v_grad_dampen`, `voltage_grad_dampen`, source/destination matrix layouts and unit suffixes. A lexicon should record mappings; changing schema keys is separate work.
- **Spelling should be a style choice, not an API migration.** Pick a prose convention for normalization/normalisation, optimization/optimisation, damping/dampening, and the spellings of neuron-model names. Keep exact import names, command flags, citations and quoted labels intact.

## 4. Minimal structure for the eventual lexicon

Use one maintained vocabulary source, not a service or catalogue database. Each entry needs: preferred term; one-sentence definition; scope; mathematical symbol; code/schema aliases; units and axes; estimator or aggregation details where relevant; source-of-truth link; and terms it must not be confused with. Do not store a globally “canonical” numerical value when defaults differ by recipe.

Start with readouts, rates/counts, checkpoint selection, participation, rhythm estimators, weight orientation and time units. Keep brief local definitions in standalone articles. Only after reviewing the source disagreements should names be adopted and references migrated. No article, schema, run or implementation was changed by this audit.
