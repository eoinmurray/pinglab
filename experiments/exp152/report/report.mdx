## Abstract

Two single-neuron Elevate controllers drive opposing muscles on a rotary joint
with a 2 g tip mass under gravity. Motor spikes activate muscles and inhibit the
peer controller; angle feedback excites each neuron. Three ROS2 Humble nodes
exchange complete spike windows at a nominal 1 ms period in Docker on separate

### Timing and execution limits

A callback advances one node and publishes its outputs. Its deadline is one
control period after its scheduled release. A short callback can still miss
its deadline if it starts late. Waiting for input windows contributes to lag
and deadline misses, but is excluded from the plotted callback duration.

### Controller network and preparation

Both sides instantiate the same network with separate state. `cfg` denotes the
recorded configuration, including the Elevate parameters, synaptic weights and
decay times shown in the appendix.

```python
import torch
from snnlab import lang
from snnlab.sim import Performance, prepare_stream
from experiments.exp152.custom.elevate import DEFINITION, register

register()

def controller_bundle(cfg):
    net = lang.Network("joint_controller", dt=cfg["dt_ms"] * lang.ms)
    motor = net.population(
        "motor", size=1,
        neuron=lang.CustomNeuron(DEFINITION, **cfg["neuron"]),
    )
    tonic = net.input(
        "tonic", shape=("time", "batch", 1),
        signal_type="continuous", unit="uS",
    )
    sensory = net.input(
        "sensory", shape=("time", "batch", 1),
        signal_type="spikes", unit="spike",
    )
    peer = net.input(
        "peer", shape=("time", "batch", 1),
        signal_type="spikes", unit="spike",
    )
    net.connect(
        tonic, motor.excitatory, name="local_bias",
        synapse=lang.CustomSynapse("pinglab.exp152.direct_conductance/v1"),
        weight=lang.Constant(1.0), initialization_scaling="direct",
    )
    for source, target, name, synapse in (
        (sensory, motor.excitatory, "sensory_drive", lang.AMPA),
        (peer, motor.inhibitory, "peer_inhibition", lang.GABA),
    ):
        net.connect(
            source, target, name=name,
            synapse=synapse(tau=cfg["synapse_tau_ms"][name] * lang.ms),
            weight=lang.Constant(cfg["weights"][name]),
            initialization_scaling="direct", constraint=lang.NonNegative(),
        )
    net.output("motor_voltage", motor.voltage)
    net.output("motor_spikes", motor.spikes)
    return lang.compile(net)

# Each controller process prepares its own stream and fixed input tensors.
stream = prepare_stream(
    controller_bundle(cfg), window_steps=1, batch_size=1,
    device="cpu", dtype=torch.float64,
    performance=Performance(compile_mode=cfg["compile_mode"]),
)
inputs = {name: torch.zeros(1, 1, 1, dtype=torch.float64)
          for name in ("tonic", "sensory", "peer")}
warm_up_with_quiet_sensory_and_peer_windows(stream, inputs, model_ms=1000)
stream.reset()
for values in inputs.values():
    values.zero_()
# Reset the local model counter before arming the shared ROS start epoch.
```

Warm-up exercises execution before ROS control starts. Its state, inputs and
model counter are reset, so it is not a scientific burn-in. During control,
`advance` preserves the neuron's six states and the synaptic states between
windows; the model is not rebuilt or reset per callback.

### Shared ROS2 scheduling

All three nodes publish `/frames/<node>` messages containing a window index,
step count and sparse `(step, unit)` events. Empty messages explicitly represent
silence. Window zero receives empty inputs; each later update consumes both
other nodes' complete preceding windows. Ordinary `/motor/<side>` and
`/sensory/<side>` messages remain available for delivery diagnostics; logical
frames supply the model inputs.

```python
def execute_node(name, sources, tick):
    origin = map_shared_ros_start_to_monotonic_time()
    for k in range(number_of_requested_windows):
        release = origin + k * period
        service_ros_until(release)
        # k == 0 receives empty frames; later windows wait for both sources.
        frames = wait_for_complete_windows(k - 1, sources, release, max_lag)
        if monotonic_time() - release > max_lag:
            stop("excessive_lag")
            break
        started = monotonic_time()
        events = tick(k, frames)
        publish_window("/frames/" + name, k, substeps=1, events=events)
        record_callback_and_deadline(started, deadline=release + period)
        # Preserve the release schedule and every model window when late.
```

`wait_for_complete_windows` services ROS subscriptions and checks the lag stop
while waiting. The nominal releases and deadlines never shift. Logical mode
finishes the requested number of model windows unless stopped; it can take
longer than the requested model duration in wall time.

### Flexor and extensor ROS2 nodes

The same callback runs in each controller process. The joint frame uses unit
zero for flexor sensory events and unit one for extensor sensory events. Peer
frames carry the other motor neuron's spikes. Inputs enter the first external
step of the callback; with this protocol each callback contains one step.

```python
def controller_tick(side, k, frames):
    peer_side = "extensor" if side == "flexor" else "flexor"
    sensory_unit = 0 if side == "flexor" else 1
    sensory_count = sum(unit == sensory_unit for step, unit in frames["plant"])
    peer_count = len(frames[peer_side])
    tonic = (cfg[side + "_initial_us"]
             if k * cfg["dt_ms"] < cfg["flexor_bias_ms"]
             else cfg["tonic_us"])
    inputs["tonic"].fill_(tonic)
    inputs["sensory"].fill_(sensory_count)
    inputs["peer"].fill_(peer_count)
    result = stream.advance(inputs)
    events = sparse_motor_events(result.outputs["motor_spikes"])
    publish_motor_diagnostics("/motor/" + side, events)
    return events  # Scheduler publishes this window even when events is empty.
```

### Joint dynamics ROS2 node

The joint encodes its old angle before updating muscles and mechanics. Received
motor spikes are divided by population size and applied once. Muscle activation
decays before the spike increment; the updated activation sets torque. Velocity
updates first, then angle, followed by hard-stop enforcement.

```python
import numpy as np
from experiments.exp152.custom.models import Joint

joint = Joint(cfg["joint"])

def joint_tick(k, frames):
    motor = np.array([len(frames["flexor"]), len(frames["extensor"])])
    motor = motor / cfg["neurons"]
    sensory = joint.encode(now=k * cfg["dt_ms"] / 1000)
    joint.advance(motor, dt=cfg["dt_ms"] / 1000)
    events = [(0, side) for side, count in enumerate(sensory) if count]
    publish_sensory_diagnostics(events)
    return events  # Controllers consume these sensory events in window k + 1.
```
